# Return of Zero Expression Corpus — Production Alignment

**Standing:** corrected execution alignment, 16 September 2026.  
**Owner:** issue #65.  
**Source authority:** `AGENTS.md`, `the-return-of-zero-central-plan.md`, `return-of-zero-orienting-principles.md`, live publication nodes and source-house protocols.  
**Material authoring surface:** isolated Point-Cloud-Demo Expression editor/engine.  

## 0. Office of this work

This repository determines **what the Return-of-Zero authored world is and what must remain answerable in its Expression corpus**.

Point-Cloud-Demo is only the isolated authoring sandbox in which the actual Expression/Profile/Scene/HTML artifacts are crafted. The same engine is already integrated into the O:I desktop cradle.

Do not:

- move essay/source authority into Point-Cloud or O:I;
- invent a second Expression runtime;
- create a corpus-specific Ta-Onta roster;
- require worktrees merely to write disjoint Profile/HTML/JSON/artifact files;
- alter canonical prose to make an Expression easier to compose.

## 1. Source packet

The parent session compiles one bounded packet per target/family from the current canonical census at a named source revision.

A packet retains, where present:

```text
canonical identity / home / register / record type
source revision and source/claim standing
section / movement / argument / concept relations
incoming / outgoing / Return refs
bounded local whole
human-amplified standing where applicable
relevant media/source refs
existing profile / Expression / occurrence refs
expected family / sequence relation
```

The packet is the **semantic burden to preserve**, not an art-direction specification.

## 2. Expression production

Each content worker turns its packet into real editable artifacts using the existing Point-Cloud editor/engine and its full K-series material body.

Typical outputs may include:

```text
ExpressionProfile / family profile
Expression / Scenes / sequence
HTML / WorldPresentation companion where required
source/file/portal refs
used glyph/image/ASCII/diagram/media
cover/capture
artifact/source binding record
```

Use existing Expression schemas and export conventions. Do not create another scene language.

Artifacts live in the dedicated Return-of-Zero production collection in Point-Cloud-Demo. This repository keeps the authoritative census/coverage/index relation back to those artifacts.

Where production exercises Ta-Onta, use the accepted QL-MEF/AW architecture.

```text
Khora → Hen → Pleroma → Chronos → Anima → Aletheia → Return
```

Work composition follows CPF / CT / CP / CF / CFP / CS.

## 4. Content-arising forms

No separate visual-procurement lane precedes production.

```text
source/content relation
→ concrete expressive need
→ find / make / adapt glyph, image, ASCII, diagram, media or form
→ verify provenance/rights where required
→ use in actual Expression
→ inspect and retain/reject/revise
→ index useful occurrence
```

The resulting bank is empirical. Repeated visual association never becomes semantic truth merely through use.

## 5. Family grammar

Repeated canonical families should reuse Profile/Scene grammar where that serves the source, while every record remains independently addressable.

Examples include A, A′, concept/episteme forms, section-room movements and other repeated carriers.

The exact family form is discovered through actual source structure and authoring tests; do not force every record type into one generic card.

## 6. Mytheme whole-first law

Whole Mythemes remain primary.

A Mytheme Expression must preserve enough of the whole relational story/work that later transformation and ending can qualify the beginning. This may require a real multi-scene sequence.

Derived figures, things, places, actions, motifs and cross-story comparisons retain exact reverse links to their whole-story occurrences. Preserve `human-amplified` standing.

Do not reduce Mytheme to decorative emblem selection.

## 7. Efficient development fan-out

The parent session owns E0: current census, source packet generation, artifact inventory, profile continuity, lane reconciliation and final coverage.

Use exactly **six content-production subagents**:

1. **Essay + section rooms** — sovereign reading path and 48-movement/room field.
2. **A + A′** — argument/conjugate repeated families and exact source/room relations.
3. **C + A/C + S + remaining Episteme** — concepts, root/relational carriers, S records and other repeated Episteme forms, split internally by target packets rather than spawning another top-level worker.
4. **Matheme** — formal/diagrammatic/source-bearing forms.
5. **Symbolon** — whole/root/spine/heads and its relation to the three nested registers.
6. **Whole Mythemes** — whole-story sequences first; derivative occurrence work follows from the wholes.

These are development/content workers, not runtime Ta-Onta Agents.

Default to the current shared checkout and disjoint artifact paths. Use branch/worktree isolation only when two workers must change the same code/source surfaces concurrently.

## 8. Parent integration and Return

E0 continuously maintains:

```text
source identity + revision
assigned worker/family
Expression/Profile/artifact refs + revision
used source/media/form refs
coverage status
source reconciliation status
human/source review status
material/craft observations
shared-engine defect refs
```

A source revision invalidates only affected packets/artifacts. Reopen those targets; do not blindly regenerate the corpus.

Shared Point-Cloud editor defects return to Point-Cloud #6. M/Bimba/M′/Ta-Onta semantic defects return to QL-MEF. O:I runtime/desktop defects remain O:I-owned.

## 9. Acceptance

The corpus production tranche is ready for submission acceptance when:

- the live canonical authored-world census has an explicit Expression/non-Expression disposition;
- the sovereign essay, section rooms and all four registers are represented according to their own source anatomy;
- repeated families retain exact addressability and source refs;
- Whole Mythemes remain narratively/relationally whole;
- artifacts are real editable Expressions generated with the existing engine;
- content-arising forms remain attributable where required;
- source changes can selectively invalidate/rebuild affected artifacts;
- generated artifacts can be loaded by the same integrated Expression engine in O:I;
- material/craft learning returns through the existing Ta-Onta/Aletheia/Epii path rather than a new corpus ontology.
