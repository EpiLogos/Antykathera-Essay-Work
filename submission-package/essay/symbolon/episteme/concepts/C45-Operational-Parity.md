# C45 — Operational Parity

**Definition.** Operational Parity is the requirement that a formal/philosophical distinction promoted into software should produce some inspectable or discriminable operational consequence. It does not require every philosophical distinction to be encoded.

The distinction exists to stop ontology from becoming decorative architecture language. If two states are said to differ but no behaviour, routing, evidence requirement, storage, permission, evaluation or test can ever discriminate them in the implementation that claims to use the distinction, the technical promotion is empty.

Its operation is **claimed distinction → identified operational locus → observable difference/failure criterion**. C39 MEF frames inquiry; C40 exposes judgment internals; C43 supplies reflexive update; C46 names the cultivation practice through which tests revise both code and concept.

Nearest neighbours are C39, C40, C43 and C46. It is not crude verificationism: concepts may remain philosophically real without software representation; parity applies when software claims to instantiate them.
