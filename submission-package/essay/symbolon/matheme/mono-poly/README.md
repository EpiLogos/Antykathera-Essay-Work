# Mono/Poly — the field of notations

The symbolon directory works with many notations in one field, and this folder holds that field. Mono/Poly rests on two grounds. In the processual pass it is the Becoming harmonic (process §4′: "Mono-Poly = Becoming — the /-side pair… the Mono going Poly… the Poly going Mono"). In the essay it is the sustained relation of whole and many: one relational whole differentiating through many real expressions, which is neither a giant entity nor a heap of atoms ([[section-rooms/arguments/A12-Mono-Poly-One-All-Whole-Many.md|A12]] **grounds** the relation, `C26 — Monoisation / Counter-Generation` names its failure mechanism, and `C54 — Commons / Non-Monopoly` is its shared-field face).

The notations defined across the matheme are binary, slash-forms, ratios, determinations, lens IDs and the CF grammar, and this folder holds them together as one countable field. It asks which notations the system implies, how each reduces or expands, and where two notations say one thing.

## Structure

- **[mono](mono.md)** — the one field. It names what every notation in the system is a notation *of*, namely `0/1` and its expressions, so that the equation is the single subject all four files carry.
- **[poly](poly.md)** — the many notations. It inventories the plurality, giving each sign's office, each formalism's point of contact and each register's dialect, with no collapse into one preferred encoding.
- **[translations](translations.md)** — the mapped correspondences with their proof boundaries. It says which reductions are derivations, which are constructions and which are named cross-register recognitions, applying the record form's three separated claims from notation to notation.

The folder feeds the [[symbolon/matheme/dia-syn/README.md|Dia/Syn]] logics, since their operations run between notations, and it returns to the [[symbolon/matheme/README.md|matheme spine]] at the Becoming position.
