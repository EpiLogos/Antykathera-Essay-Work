# Expression Corpus Production Map

**Owner:** issue #65  
**Standing:** corrected executable production map, 16 September 2026.  
**Ground:** `docs/EXPRESSION-CORPUS-PRODUCTION-ALIGNMENT.md` + repository authority in `AGENTS.md`.  
**Material authoring:** isolated Point-Cloud-Demo editor/engine; O:I desktop already contains the integrated runtime engine.

## E0 — parent integration

The parent session owns:

- current canonical authored-world census at a named revision;
- target/family packet generation;
- assignment and non-overlap;
- source→artifact inventory;
- shared Profile continuity;
- source reconciliation after accepted changes;
- final coverage and submission handoff.

The parent does not author every target serially.

## Six content-production workers

### E1 — essay + section rooms

One development subagent owns the sovereign reading path plus the eight rooms / 48 movements, preserving exact previous/next/Return and links into the canonical field.

Output: essay/room Expression grammar, addressable room/movement Scenes where useful, source/portal refs and artifact bindings.

### E2 — A + A′

One development subagent owns the argument and conjugate families as repeated source-bound forms.

Output: family Profile/Scene grammar + independently addressable records + exact room/source/transverse relations.

### E3 — C + A/C + S + remaining Episteme

One development subagent owns the concept/root/S and remaining repeated Episteme carriers. Work target-by-target from bounded packets and preserve type/source distinctions; do not collapse the field into one generic card.

Output: reusable Profiles where warranted + exact individual artifact bindings.

### E4 — Matheme

One development subagent owns the canonical Matheme tree and its formal/diagrammatic source-bearing Expression forms.

Output: formal Profiles/Scenes/HTML companions as appropriate, retaining exact mathematical/source standing.

### E5 — Symbolon

One development subagent owns the Symbolon whole/root/spine/heads and its containing relation to Matheme/Mytheme/Episteme.

Output: Symbolon whole/register Expression relation and root traversals without treating Symbolon as an omitted wrapper or a fourth sibling bucket detached from the whole.

### E6 — Whole Mythemes

One development subagent owns Whole Mythemes first. Build complete sequenced Expressions where required so transformation/ending can qualify the beginning.

Only after wholes exist should derivative figures/things/motifs/places/actions and cross-story occurrences be indexed back to exact moments. Preserve `human-amplified` standing.

## Shared production law

Every worker receives a bounded canonical packet, then crafts actual editable artifacts using the existing Point-Cloud-Demo authoring system.

```text
canonical packet
→ current family/Profile basis
→ actual Expression/Profile/Scene/HTML authoring
→ inspect/play/capture where useful
→ retain/revise/reject form choices
→ write artifact into Return-of-Zero production collection
→ return source/artifact binding + material observations to E0
```

No separate scene schema. No separate corpus runtime. No mandatory worktree for disjoint artifact generation.

## Visual material

There is no visual-procurement worker.

Forms arise from actual content needs, are provenance/rights checked when necessary, tried in the real Expression, and only then retained/indexed for reuse.

## Ta-Onta runtime law

## Coverage inventory

E0 maintains a generated inventory only:

```text
source id + revision
home / register / type
worker/family
Expression/Profile/artifact ref + revision
Point-Cloud output path
source/media/form occurrence refs
coverage status
source-reconciliation status
review/acceptance status
shared editor defect refs
```

The inventory never supersedes the canonical authored-world census.

## Reconciliation

After accepted source changes:

```text
new canonical census/revision
→ diff affected identities/relations/source standing
→ invalidate affected packets/artifacts only
→ reopen those production targets
→ retain still-valid authored variants
→ report retired/orphaned bindings
```

## Gate

Close the production tranche only when the current canonical census has explicit coverage/disposition, all four registers and section/essay relations are represented according to source, Whole Mythemes remain whole, generated artifacts are editable and source-bound, and the same Expression engine already integrated into O:I can load/inhabit the accepted outputs.
