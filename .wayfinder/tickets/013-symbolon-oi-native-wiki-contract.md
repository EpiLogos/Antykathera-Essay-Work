# Define the Symbolon ↔ O:I native Wiki and knowledge-layer contract

## Question

What exact minimal contract lets Symbolon remain the canonical authored OKF world while becoming a first-class O:I Wiki/Projection and AIKit-navigable knowledge field, with authority/provenance depth and explicit return rather than ontology collapse?

## Required work

Read the current Symbolon publication ontology, OKF conventions, page identity/status/link/return contracts, and current O:I Explore/Wiki/Projection architecture plus AIKit Knowledge Navigation and product-understanding/account-authoring Skills.

The contract must preserve:

- one canonical Symbolon record identity and native home;
- root Symbolon / Matheme / Mytheme / Episteme distinctions;
- `record_type`, register, claim status, source relation, citation/quotation readiness and exact return targets;
- native written-link relations and block-level anchors where already required;
- O:I `Projection` as representation rather than transfer of source authority;
- browser/Explore authoring as Projection revision until an explicit source-return proposal is accepted;
- `SharedField ≠ WikiSpace ≠ Context`;
- Wiki relation ≠ Contribution relation ≠ learned KnowledgeRoute;
- human and agent readings sharing the same Projection identity without forcing agents to scrape rendered HTML.

### Authority/operation ladder

Design the wiki affordance needed to traverse from an authored concept into the layers that accrue around it without flattening them:

```text
authored position / root relation
        ↓
principle / argument / constitutional intent
        ↓
design relation / product responsibility
        ↓
architecture / contract / operation
        ↓
implementation / experiment / evidence
        ↓
finding / critique / returned pressure
        ↺
explicit proposal back toward authored ground
```

This ladder is provenance-sensitive, not a claim that lower layers are subordinate in all questions. The relevant authority depends on the question being asked.

### AIKit integration

Use existing first-party seams rather than inventing another knowledge system:

- `product-understanding` for provenance-aware traversal;
- `structured-account-authoring` for coherent readings over a Wiki/research corpus;
- `projection-authoring` for selective O:I representation;
- existing Knowledge Navigation operations such as `sources/search/read/relations/route/frame/explain/history`;
- renderer/account surfaces only as representations of structured reading.

Identify any genuine missing wiki functionality needed to expose authority layers, operational relations, projection state, return proposals and O:I product links. Separate **needed product enhancement** from essay-repo metadata changes.

### O:I native projection

Specify how *The Return of Zero* can become the first genuine authored O:I world for Explore acceptance:

- source world and WikiSpace identity;
- projection root and revision identity;
- linear essay reading and bounded local whole;
- LIST/TREE/GRAPH traversal from the same canonical relations;
- deep links into Matheme/Mytheme/Episteme;
- relation from essay concept to O:I/product/research surfaces;
- structured agent reading;
- publication/selection boundary;
- source-return path;
- provenance receipt sufficient for technical/submission acceptance.

Do not implement the O:I product changes in this ticket. Produce the contract and explicit downstream requirements.

## Done when

`SYMBOLON-OI-WIKI-CONTRACT.md` defines a coherent source→projection→encounter→return architecture; no Symbolon ontology is renamed merely to suit O:I; no O:I whole-level relation steals native record semantics; the existing AIKit Skills/Knowledge Navigation are reused where real; missing product functionality is named as a precise requirement; and the essay can serve as an actual future O:I Explore acceptance world rather than a static linked document set.
