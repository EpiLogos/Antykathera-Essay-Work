# Synthesize the capstone and register it into the quilt programme

## Question

What additive and superseding decisions follow from the completed Objective Internality traversal, §5/§5→0 capstone quilt and Symbolon/O:I contract, and how must they be registered so the existing harmonisation history remains intact while the proposed 48-movement map becomes current?

## Required work

Read the complete capstone output plus `working/harmonisation-2026-08-12/decisions.md`, `POST-HARMONISATION-STATE.md`, the proposed sections map, the parallel harmonised quilt and plain-English flow.

Create `CAPSTONE-DECISIONS.md` as a new dated decision series. Do not rewrite the A/B/C/D/E record as though this material had been known on 2026-08-12. For every capstone decision state:

- antecedent decision(s) or movement(s);
- new source/pressure;
- whether it adds, sharpens, repositions, supersedes-in-office, or leaves unchanged;
- exact argument/movement/concept/path consumers;
- claim/register status;
- publication office;
- source/evidence debt;
- whether Frank ratification is still required.

### Preservation census

Account for every affected accepted technical element, especially the existing six §5 movements and six §5→0 movements. Each must end as:

- linear-bearing;
- supporting-visible;
- radial-depth;
- or genuinely redundant with an explicit reason and named surviving carrier.

No silent disappearance is permitted.

### Register the capstone

Append a dated capstone registration/supersession section to:

`submission-package/essay/quilt/2026-08-02-PARALLEL-HARMONISED-QUILT.md`

The append must preserve the quilt as provenance: no rewriting older dated decisions to make them look prescient.

Regenerate `working/harmonisation-2026-08-12/sections-map-proposed-changes.md` or create a clearly named successor if modifying that historical file would confuse provenance. The current proposal map must include every capstone effect before T07.

Update the plain-English flow only if the capstone proves a map-level statement there materially stale or misleading; do not begin manuscript drafting.

### Acceptance draft

Create `CAPSTONE-ACCEPTANCE.md` with:

- complete deliverable census;
- preservation census;
- unresolved contradictions and debts;
- mechanical checks run;
- self-audit findings;
- exact candidate questions requiring T07/Frank decision;
- exact downstream tickets whose scopes changed;
- technical-suite acceptance bar and which parts remain external work rather than completed software.

## Done when

The capstone exists as a dated, traceable extension of the harmonisation programme; the movement proposal map is current; no accepted content disappears without disposition; no section-room canonical propagation has occurred; and the package is ready for a fresh cold auditor rather than for self-certification.
