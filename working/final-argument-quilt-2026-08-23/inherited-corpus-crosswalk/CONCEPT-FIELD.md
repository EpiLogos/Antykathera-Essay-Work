# Inherited Concept-Bearing Field

Status: active recursive recovery; **not** a list of concepts to preserve.

## What a concept is for in this programme

A future concept node is justified when the newly minted argument requires a stable, instituted distinction that multiple records can rely upon. Existing files are evidence that a distinction has been developed; they are not proof that its current boundary, name or register is correct.

The live `concepts/` directory contains developed controlled-definition records plus a `reference-notes/` recovery shelf. The shelf's own README says those notes are quilt-pending working material recovered from an earlier deletion and must resolve through quilting into concept, argument or source architecture. They are neither authority nor automatic concepts.

Accordingly the recovery field includes:

```text
developed concept nodes
+ recovered/reference notes
+ deprecated/legacy definitions
+ concept-bearing arguments, etymologies, roots, maps and deep write-ups
= candidate-bearing concept field
```

Native 018 later decides which distinctions ought to become concepts.
